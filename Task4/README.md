## Структура исходного VCF

VCFv4.2, сборка `GRCh38`, источник входных вариантов указан в заголовке: пример Ensembl VEP release 116. Координаты `POS` нумеруются с 1 и относятся к положительной цепи референса.

| Поле | Значение |
| --- | --- |
| CHROM | Хромосома |
| POS | Позиция в референсном геноме |
| ID | Исходный идентификатор rsID |
| REF | Референсный аллель |
| ALT | Альтернативный аллель |
| QUAL | Оценка качества варианта |
| FILTER | Статус фильтров |
| INFO | Дополнительная аннотация |

В данном файле `QUAL`, `FILTER`, `INFO` равны `.`: значения не заданы; `FILTER=.` не следует считать `PASS`. Полей FORMAT и SAMPLE нет, поэтому генотип, зиготность и глубина покрытия неизвестны.

## Методика

### Ensembl VEP

- Endpoint: `POST https://rest.ensembl.org/vep/homo_sapiens/region`.
- Ensembl release **116**, сборка **GRCh38**, набор транскриптов **Ensembl**.
- Вход: все 50 VCF-записей с исходными идентификаторами и аллелями.
- `canonical=1`, `mane=1`, `hgvs=1`, `protein=1`, `numbers=1`, `transcript_version=1`, `variant_class=1`.
- Все возвращённые транскрипты сохранены: опции `pick`, `per_gene`, фильтрация до MANE или canonical не включались. Прочие параметры оставлены по умолчанию API.

Правило свёртки до одной строки: берётся **глобальное `most_severe_consequence` VEP**. Среди транскриптов, поддерживающих именно это последствие для нужного ALT, приоритет последовательно имеют **MANE Select → canonical → protein_coding → transcript_id по алфавиту**. Это наше явное правило свёртки; оно не выдается за стандартный VEP `--pick`.

Если максимальное последствие не встречается на MANE, выбирается другой транскрипт, а MANE и его последствия остаются в отдельных колонках. Для данного набора это относится к 9 вариантам: `rs1135638`, `rs10576`, `rs5759611`, `rs34292743`, `rs5750728`, `rs114704208`, `rs114689408`, `rs35429467`, `rs114043304`. Поэтому число missense зависит от правила выбора транскрипта. Биотип `nonsense_mediated_decay` у выбранного транскрипта сам по себе не означает, что рассматриваемый SNV вызывает NMD.

Исходный `rs61735928` объединён в dbSNP с актуальным `rs20550`: это отдельно проверено через NCBI RefSNP API и сохранено в `raw/dbsnp/rs61735928.json`. В таблице `original_id` сохраняет исходное значение, `rsid` содержит актуальное, а `rsid_status=merged` объясняет различие. Это также показывает, почему одного поиска по исходному rsID недостаточно.

### ClinVar

Использованы NCBI ESearch, ESummary и EFetch (VCV XML, `is_variationid=true`). Объединены результаты поиска по rsID и независимого поиска по хромосоме и позиции: `[CHR]` + `[CPOS]` (синоним поля `[chrpos38]`, текущая сборка GRCh38). Ненайденные термы `phrasesnotfound` сохранены как отрицательный результат поиска; ошибочные поля и сетевые ошибки не трактуются как отсутствие записи.

Классификация переносится только при **точном совпадении GRCh38 + CHROM + POS + REF + ALT** с `ClassifiedRecord/SimpleAllele/Location/SequenceLocation` в XML. Записи другого ALT и изменения нескольких оснований исключены. Например, для `rs116555717` подходит **VCV003305447.2, T>C**, с конфликтующей классификацией; **VCV002585196, T>G** относится к другому изменению и не переносится.

Берётся актуальная агрегированная **GermlineClassification** уровня VCV, вместе с версией записи, датой оценки, review status, объяснением конфликта и связанными состояниями. Если записи нет, `clinvar_present=no`, а классификация `NA`. Метки VUS и конфликтов не превращаются в вывод о патогенности.

### gnomAD

Endpoint: `POST https://gnomad.broadinstitute.org/api`, GraphQL, набор **`gnomad_r4`**, референс **GRCh38**, ключ варианта `CHROM-POS-REF-ALT`. Точное тело каждого запроса сохранено в `raw/requests.json`. Название `gnomad_r4` - идентификатор набора в API; более точный minor-release API в этом ответе не сообщает, поэтому он не придуман.

Сохраняются **AF, AC, AN, filters отдельно для exome и genome**. Основная колонка `gnomad_af` использует genome AF при пустом списке фильтров (PASS) и AN>0; при отсутствии пригодных genome-данных используется exome с теми же условиями. Источник указан в `gnomad_af_source`. Выбор genome как основного источника - единое правило для учебной таблицы; обе когорты доступны для сравнения. AC/AN двух когорт не суммируются, поскольку нельзя предполагать отсутствие перекрытия участников.

AF обозначает долю **альтернативного аллеля из VCF**, а не обязательно minor allele frequency. Например, для `rs1135638` ALT является частым аллелем с AF около 0,783. `NA` означает, что данных нет или поле неприменимо; это не ноль. Ошибки соединения повторяются, а неизвестная ошибка API останавливает обработку.

## Воспроизведение

Сборка и проверка на сохранённых ответах выполняются **без сети и сторонних Python-пакетов**:

```bash
cd "$HOME/Downloads/BioInf/Task4"
python3 scripts/build_results.py
python3 scripts/verify_results.py
```

Для получения отсутствующих исходных ответов из публичных баз:

```bash
python3 scripts/fetch_annotations.py
```

Скрипт использует кеш `raw/` и не заменяет существующие ответы: это позволяет воспроизвести снимок от 02.11.2026. Для новой аннотации на другую дату следует использовать отдельную копию исходного файла и скриптов с пустым `raw/`; версии и ответы баз могут измениться. Токены и личные данные для этих запросов не нужны.

Необязательное восстановление PDF:

```bash
python3 -m pip install -r scripts/requirements-report.txt
python3 scripts/make_report.py
```

Для кириллицы нужен TrueType-шрифт: скрипт ищет Arial на macOS или DejaVu Sans на Linux. Другие пути передаются через `--font-regular` и `--font-bold`. Готовый PDF включён в решение, поэтому для чтения отчёта ничего устанавливать не требуется.

Проверка сверяет 50 уникальных записей и исходный порядок, статистику замен, равенство CSV/TSV, поддерживающий транскрипт VEP, точные аллели ClinVar, AF=AC/AN внутри выбранной когорты, неоднозначные случаи и SHA-256 всех исходных ответов. Файл `results/verification.txt` содержит итог проверки.

Локальное правило `.gitignore` сохраняет `input/student_06.vcf` доступным для Git, несмотря на глобальное правило `*.vcf` в корне репозитория.
